# Android 模拟器独立验收能力需求

## 目标与现状

目标是在不依赖用户真机、数据线或用户代为输入的情况下，由自动化与可观察的 Android 模拟器完整验收安装包：能执行真实 WebView 用户旅程，交替操作桌面与手机，复现弱网和前后台切换，并把服务器事实、本机副本、业务投影和屏幕结果关联起来。测试完成后才交付供用户安装的 Android 应用安装包（Android Application Package，APK）。

目前 `test-android-apps` 的 Android Emulator QA 指引及本机工具已支持 Android 调试桥（Android Debug Bridge，ADB）枚举设备、安装和启动、触控/滑动/返回、截图、`logcat`、`uiautomator dump`。本轮还可在模拟器查看本地 SQLite 与同步游标、调整分辨率和像素密度、模拟短暂断网。实际 Tauri WebView 的 UI 树只暴露根节点；现有 `adb input text` 无法可靠完成中文、长文本和特殊字符的录入，靠截图坐标与虚拟键盘操作成本高且脆弱。因此此前完整录入与双端学习路径被暂缓，不能视为工具已经通过这些场景。

## 必需能力

| 能力 | 操作接口与要求 | 可验收结果 |
| --- | --- | --- |
| 可靠文本注入 | 对当前焦点输入框直接写入或粘贴 Unicode 文本，覆盖中文、英文、换行、引号、标点、短语、长文本和空串；支持替换、追加、选择范围、提交/取消。实现可采用受控剪贴板、辅助输入法或 WebView 自动化接口，但应由统一工具暴露 `fill`/`paste`，不要求逐字点虚拟键盘。 | 对录入原文、第二步表单、搜索、设置项做写入后读回断言；输入后焦点、滚动和软键盘状态可检查。敏感值只在测试运行时注入，日志、截图及报告遮盖。 |
| 语义元素发现与操作 | 读取 WebView 中按钮、文本框、对话框、列表项的角色、名称、稳定测试标识、可见性、启用态和屏幕边界；按语义点击、输入、滚动、等待状态。缺少无障碍节点时提供经验证的 WebView 调试桥或应用测试构建接口。 | 脚本能按“开始测试”“下一词”“立即同步”等语义定位，出现多个同名控件时可限定容器；坐标只作为有截图证据的回退路径。 |
| 完整设备状态控制 | 安装、覆盖安装、冷启动、杀进程、前后台、屏幕旋转、主题、字体缩放、导航模式、状态栏和软键盘；精确设置与 OPPO Find X7 截图等效的约 360×792 CSS px 视口，并记录物理像素、密度、实际 WebView 视口及安全区。 | 同一脚本可重复核对小视口抽屉、顶栏、滚动、触控与恢复；截图包括完整屏幕，背景铺满而内容避开系统栏。 |
| 网络与时间控制 | 分别控制两端离线、弱网、延迟、丢包、恢复及前后台联网；能记录每次 push/pull 的请求结果与时间，必要时使用可重复的测试时钟。 | 本地最终确认后尽快排入出站并尝试推送；断网期间本地操作不断；恢复后自动补传补拉；手动同步作为失败兜底单独测。 |
| 双客户端独立状态 | 桌面真实 App 与至少一个 Android 模拟器持有不同设备身份及各自本地库；必要时增加第二个模拟器。测试数据有唯一标识并可按产品方式归档。 | 可以让两端同时停在同一测试会话，交替确认词，再检查两边原页变化；不存在共享数据库或测试桩造成的假阳性。 |
| 跨层可观测性 | 脱敏采集 WebView JavaScript 异常、Rust/Android 原生日志、请求结果、服务器事件序号、本机同步游标、出站队列、领域重放结果和会话当前位置；release 候选包发生错误时也有安全的诊断途径，或提供与候选包同源且行为一致的诊断构建。 | 每个失败可回答“未到服务器、未拉到本机、已拉到但未投影、已投影但 UI 未刷新”中的哪一步；异常边界有堆栈和操作时间线。不得把别的应用日志或服务器 200 推断为本 App 全链路成功。 |
| 视觉与性能证据 | 每步全屏截图、必要时录屏；测首屏、页面切换、滚动和液态玻璃动效的帧时序、卡顿和内存趋势。 | 可复核主题、安全区、中文换行、输入态、错误态和前后台恢复；性能结论有设备配置、采样区间与原始数据。 |
| 可重放场景脚本 | 对“动作—预期持久事实—预期当前屏幕”同时断言，保留按设备分离的截图、脱敏日志和失败时数据库快照；失败可从清晰基线重跑。 | 双端开放会话、两步提交、未提交初判被远端覆盖、同词交错、录入草稿本地化、重复词弹窗、弱网恢复等均由模拟器真实操作覆盖。 |

## 建设与验收顺序

1. 先补可靠文本注入和 WebView 语义操作，再重跑录入、测试、复习与设置的单机完整旅程；这两个缺口是本轮被迫跳过用户路径的直接原因。
2. 建立跨层诊断与双客户端脚本，优先复现第四轮遗漏的“手机答两词、桌面答三词、手机原页继续”及反向路径。每次确认只在第二步提交事件；远端已确认事件到来后检查本机会话和当前卡片，不以服务器游标作为唯一通过条件。
3. 加入断网、延迟、前后台和重启组合，再用与交付包同源的 Android 构建验收。所有本轮遗留的“暂缓”项目必须逐项变为有证据的通过或明确阻断；不得要求用户真机补测才能发现基础业务缺陷。

模拟器通过是向用户交付 APK 的必要质量门；用户真机实测仍可发现机型特有问题，但不承担常规业务流程的首轮验收职责。若工具暂时无法提供某项能力，应把受阻路径及可观察边界写入验收记录，并停止宣称 Android 端到端通过。
