# 同步服务器部署留档（本地哑服务器）

- 性质：**本轮（2026-09-19 夜）只做本地留档，未执行任何远端连接、上云或 SSH 操作**（第一轮硬约束）。本文是后续轮次执行真实上云时的操作蓝本，执行前必须经用户确认。
- 服务器实现与测试事实见 `server/`（Fastify 5.12.3 + better-sqlite3 13.0.3，测试 46 项全绿）；本文只记录运行与部署口径。

## 一、本地运行（本轮已验证的形态）

```bash
# 开发启动（默认 127.0.0.1:8787，库文件 server/data/ebbinghaus.db）
rtk pnpm server:start

# 带显式配置启动（CLI 参数优先级最高，其次环境变量，见 server/src/config.ts）
rtk pnpm --filter @ebbinghaus/server start -- --db ./data/dev.db --token <随机token> --host 127.0.0.1 --port 8787

# 在线备份（better-sqlite3 backup API，绝不 cp 正在写入的库文件）
rtk pnpm server:backup
```

配置优先级（`server/src/config.ts`）：CLI `--db/--token/--port/--host` > 环境变量 `EBB_SERVER_DB_PATH / EBB_SERVER_TOKEN / EBB_SERVER_HOST / EBB_SERVER_PORT` > 默认值（`server/data/`、`127.0.0.1`、`8787`）。**token 未提供时启动直接失败（fail fast），样例 token 与真实 token 都不入仓库。**

## 二、后续轮次上云蓝本（本轮禁执行）

1. **前置确认**：与用户确认目标机器（腾讯云，`ssh alex`）与维护窗口；确认不再改动本文件之外的线上配置。
2. **构建产物**：服务器为 tsx 直跑 TS 源码形态，上云需在服务器侧安装 Node 24.21.0 LTS（mise）+ `pnpm install --prod`（或改用打包产物，届时按当轮决策）。
3. **数据库初始化**：首次启动自动幂等建库（`schema_migrations` 版本表）；库文件放服务器数据目录并纳入服务器侧定时备份（`server:backup` + cron，备份文件保留策略届时确认）。
4. **进程托管**：systemd 单元示例（留档，届时核对用户服务器实际 init 形态）：
   ```ini
   [Unit]
   Description=Ebbinghaus Sync Server
   After=network.target
   [Service]
   WorkingDirectory=/opt/ebbinghaus/server
   Environment=EBB_SERVER_DB_PATH=/opt/ebbinghaus/data/ebbinghaus.db
   Environment=EBB_SERVER_TOKEN=<部署时生成，不入仓库>
   Environment=EBB_SERVER_HOST=127.0.0.1
   Environment=EBB_SERVER_PORT=8787
   ExecStart=/usr/bin/env tsx src/index.ts
   Restart=on-failure
   [Install]
   WantedBy=multi-user.target
   ```
   绑定 127.0.0.1，只经 Cloudflare Tunnel 暴露，不开公网端口。
5. **暴露方式**：沿用既有 Cloudflare Tunnel（代码只认客户端配置的 Base URL；隧道配置属用户线上资产，本轮禁改）。**禁止直连公网暴露**（直连涉及 ICP 备案，见技术决策第十三章）。
6. **真实数据迁移**：执行 `AGENTS.md`「真实数据上云迁移闭环」全部步骤（备份先行、幂等脚本、外键/完整性检查、双端重放一致验证），该操作一次性不可逆，执行前必须用户确认方案。

## 三、客户端接入口径

- 客户端只配置 `Base URL + Bearer access token`（技术决策第五章）；Base URL 指向 Tunnel 域名。
- 本轮与 localhost 联调阶段：Base URL = `http://127.0.0.1:<port>`，token 为本地随机生成。
