# 同步服务器部署与维护

## 当前部署

- 腾讯云主机通过 `ssh alex` 管理；代码位于 `/opt/ebbinghaus`，SQLite 数据目录位于 `/opt/ebbinghaus/data`。
- `ebbinghaus-sync.service` 由 systemd 托管并已设置开机启动，单元文件与仓库的 `server/deploy/ebbinghaus-sync.service` 对应。服务只监听 `127.0.0.1:8787`。
- 服务通过单元文件中的 PATH 使用并排安装在 `/opt/ebbinghaus/runtime/node-v24.21.0-linux-x64` 的 Node.js 24.21.0；系统 `/usr/bin/node` 不随本项目改变。
- Cloudflare Tunnel 把 `eb-data.edgarzhong.fyi` 转发到该回环端口；不开放同步服务的公网监听端口，也不加 Cloudflare Access。同步接口仍必须通过 Bearer token 鉴权，缺少或错误令牌返回 401。
- 令牌保存在服务器 `/etc/ebbinghaus/server.env`，该文件不入仓库。客户端令牌以本机加密密文保存；不得在命令输出、文档或日志中打印明文。
- 目前云端权威库和 V2 本地库均为**可修改的验收测试数据**。V1 演练备份也是测试样本；正式生产库来源尚未确认，不得把演练结果称为生产数据切换。

## 运行与检查

```bash
# 本机开发服务：默认 127.0.0.1:8787，默认库为 server/data/ebbinghaus.db
rtk pnpm server:start

# 服务器状态及 Tunnel 规则检查
rtk ssh alex 'systemctl status ebbinghaus-sync.service --no-pager'
rtk ssh alex 'cloudflared tunnel ingress validate'

# 公开健康检查与未鉴权拒绝检查；不要在 URL 或命令行中放令牌
rtk curl -fsS https://eb-data.edgarzhong.fyi/health
rtk curl -sS -o /dev/null -w '%{http_code}\n' https://eb-data.edgarzhong.fyi/settings
```

配置优先级见 `server/src/config.ts`：命令行 `--db/--token/--host/--port` 高于 `EBB_SERVER_DB_PATH / EBB_SERVER_TOKEN / EBB_SERVER_HOST / EBB_SERVER_PORT`，再高于开发默认值；未提供 token 时生产入口拒绝启动。

## 在线备份与恢复

运行中的 SQLite 数据库使用预写日志（Write-Ahead Logging，WAL）；只复制 `.db` 文件可能丢失尚在 WAL 中的事务。备份入口 `server/src/backup.ts` 使用 SQLite 在线备份接口，不覆盖旧备份。

```bash
# 本机开发库
rtk pnpm server:backup

# 服务器权威库；明确传入库路径和输出目录，避免落到开发默认路径
rtk ssh alex 'cd /opt/ebbinghaus && pnpm --dir server backup -- --db=/opt/ebbinghaus/data/ebbinghaus.db --out-dir=/opt/ebbinghaus/data'
```

恢复前先停止服务，保留现有库与在线备份，检查目标备份的 `PRAGMA integrity_check` 和关键记录数；再切换库文件并启动服务。演练库可按测试需要归档和重建；正式生产库必须按 `AGENTS.md` 的迁移闭环执行，保留至少一份经核验的原始数据在线备份。

## V1 数据演练与正式切换边界

`packages/migration` 提供 V1 SQLite 到 V2 客户端库的幂等导入与审计；先从 V1 在线备份导入到**新的** V2 库，再由桌面客户端通过 outbox 上传到权威服务器。演练已覆盖事件、词内容、词书结构、Space 和设置，也验证过新客户端从云端全量拉取。正式生产库未识别前，只能把这些操作认定为测试迁移。正式切换时应重新确认源库、生成并核验在线备份、核对事件/词条/设置计数与双客户端重放结果。
