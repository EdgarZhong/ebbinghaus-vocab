# 同步服务器部署与维护（自托管指南）

Ebbinghaus 的云同步服务器刻意保持"哑"：只做 Bearer 令牌鉴权、协议校验、事件去重、存储与增量查询，不包含任何学习算法。你可以把它部署在任何自己的主机上，客户端构建时通过 `VITE_CLOUD_SYNC_URL` 指向它即可。

## 部署形态

- 服务代码在 `server/`（Node.js + Fastify + better-sqlite3），建议经 systemd 托管并开机启动；参考单元文件见 `server/deploy/ebbinghaus-sync.service`。
- 建议只监听回环地址 `127.0.0.1:8787`，由反向代理或隧道（如 Cloudflare Tunnel、nginx、Caddy）以 HTTPS 对外暴露；同步接口仍必须通过 Bearer 令牌鉴权，缺少或错误令牌返回 401。
- 令牌通过环境变量或命令行参数提供，保存在服务器本地的环境文件中（如 `/etc/ebbinghaus/server.env`），不要写入仓库、日志或命令行历史。客户端令牌以本机加密密文保存。

## 运行与检查

```bash
# 本机开发服务：默认 127.0.0.1:8787，默认库为 server/data/ebbinghaus.db
pnpm server:start

# 部署后：健康检查与未鉴权拒绝检查；不要在 URL 或命令行中放令牌
curl -fsS https://你的同步服务器域名/health
curl -sS -o /dev/null -w '%{http_code}\n' https://你的同步服务器域名/settings   # 应为 401
```

配置优先级见 `server/src/config.ts`：命令行 `--db/--token/--host/--port` 高于 `EBB_SERVER_DB_PATH / EBB_SERVER_TOKEN / EBB_SERVER_HOST / EBB_SERVER_PORT`，再高于开发默认值；未提供令牌时生产入口拒绝启动。

## 在线备份与恢复

运行中的 SQLite 数据库使用预写日志（Write-Ahead Logging，WAL）；只复制 `.db` 文件可能丢失尚在 WAL 中的事务。备份入口 `server/src/backup.ts` 使用 SQLite 在线备份接口，不覆盖旧备份。

```bash
# 本机开发库
pnpm server:backup

# 生产库：明确传入库路径和输出目录，避免落到开发默认路径
pnpm --dir server backup -- --db=/你的数据目录/ebbinghaus.db --out-dir=/你的备份目录
```

恢复前先停止服务，保留现有库与在线备份，检查目标备份的 `PRAGMA integrity_check` 和关键记录数；再切换库文件并启动服务。
