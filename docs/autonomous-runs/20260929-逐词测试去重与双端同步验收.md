## 本轮完成的调整

- 逐词测试页将“暂停并返回”放在桌面左上角；初判“不认识”后可点较窄的“点错了”，该操作不提交学习事件，当前词移到本机会话队尾并立刻进入下一词，轮到队尾时重新初判。
- 移动端测试按钮不再显示 Enter/Backspace 快捷键。揭晓页“点错了”位于卡片底部，增加系统导航安全区间距。
- “点错了”顺序此前只改了内存，SQLite 普通进度更新不会写 `words_json`。本轮增加专用受限重排接口并覆盖 SQLite 测试，确认只可重新排列既有计划，不能增删词或改计划时间。
- 重复词弹窗改为清晰实色面板；条目可展开查看新旧释义和用法；可全选、多选、批量处理、修改决定并查看处理进度，保留取消入口。
- 普通设置的开关和选项改动后立即保存；有效文本和数值在失焦后保存。目标保持率遵循用户确认，保留原保存与连续两次确认流程；API 密钥仍独立提交。
- 已落实草稿仅本机保存的同步边界，正式词条与义项仍由同步流程处理。
- 开放测试会话以本机已拉取的最终作答事件重基准；最终确认校验页面原展示词条身份，避免同步在初判后推进时把回答记到下一词。

## 2026-09-30 末词暂缓边界复查

用户指出“点错了”必须切到另一个词。复查发现旧需求规格和自动化测试错误允许“只剩一个未答词时，点击后仍重复显示该词”。当前源码已改为：还有其他待测词时才允许暂缓；只剩一个时按钮禁用并解释原因，两种应用服务也拒绝无效调用。词书、常规模式及界面回归共 52 项定向测试通过，完整套件、类型检查和 Playwright 也已复跑通过。新 APK 已覆盖安装，真实触控验收推进至只剩 `Occupation`，揭晓后确认“点错了”禁用且原因可读，末词没有被错误重显。完整屏幕证据见 `app/e2e/__screenshots__/20260930-android-release-point-wrong-last-word-disabled.png`。新 macOS `.app` 也已替换；其界面仍受主机锁屏限制，未完成原生目视验收。
