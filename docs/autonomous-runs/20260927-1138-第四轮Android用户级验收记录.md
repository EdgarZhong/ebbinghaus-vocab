- 每条用户路径记录预期、实际、截图或日志证据和结论；缺陷修复后需再次运行该路径及受影响邻近路径。

这里的“云端权威”指服务器持有已提交事实；客户端仍必须把这些事件投影到当前开放会话和界面。现有实现缺少这一步。仅增加轮询频率、长连接或反复点“立即同步”，不能修正已拉到事件却仍显示旧会话的问题。相反，若真机当时确实未拉到事件，传输路径也需独立查证。两条路径在下一轮须分别用游标、事件、会话投影与可见卡片取证。

页面错误边界的具体异常尚未确认。由于“重新加载”可恢复且用户已明确降低其优先级，下一轮先保证双端学习一致性和可观测性；后续拿到可定位的异常栈再修，不以截图推断根因。

### 为什么此前验收没有发现

复查本轮验收记录与上一轮完成汇报，A8 真实操作是两端创建、归档 Space 与一次短断补拉；它证明目录内容同步，却没有在两端同时保留同一 List 的开放测试会话，也没有交替确认学习事件。模拟器命令行文字输入受限后，这条学习写入路径被如实列为暂缓，但候选包仍交由真机使用；“Space 双向同步”在看板和汇报中容易被读作整个学习过程无缝衔接。用户一进入真实的“手机答两词 → 桌面答三词 → 手机继续”路径，就触发了测试矩阵的空格。

更深层的测试盲点是验证了**传输**，没有同时验证**投影与界面**。同步集成测试可以证明事件到达、游标前进和队列清零；单端页面测试可以证明本机暂停恢复；二者都不能证明“已有本机开放会话时，远端事件到达后当前卡片如何变化”。会话快照被当成权威位置，恰好避开了这些测试各自覆盖的边界。用户此前说不要求极低延迟，并不等于允许已同步事件长期不显示；把性能要求误读成一致性豁免，是验收设计错误。

后续交付报告必须按“对象类型 × 两端页面状态 × 操作交错 × 网络状态 × 可见结果”列用例，并区分：事件是否在服务器、客户端是否拉取、领域状态是否重放、开放会话是否收敛、当前页面是否更新。任何一层缺证据，只标该层已验证；不得从游标一致推断用户可见状态一致。测试能力不足时明确停在候选包，不以用户真机充当缺失的模拟器验收步骤。

### 下轮重验门槛

1. 两端都打开同一词书 List 测试；手机最终确认两词，桌面在自己的开放会话中最终确认三词。手机保持测试页时自动跳过远端已确认词，任务行、剩余数和当前卡片在原页更新；退出、重进、重启后的结果一致。反向方向也执行。
2. 一端只完成第一步初判，另一端完成该 Word 的第二步确认；前者拉取后舍弃未提交初判，不产生答案事件，不误把旧判断记到下一词。两端几乎同时确认同词时不得无故推进状态；已确认词条与事件不得丢失。
3. 录入的原始文本、模型整理结果及未提交表单只在本机；两端正式保存后的词条均可见，重复检查弹窗可完成多项冲突处理。断网、本地写入、恢复、前后台切换与手动兜底分别验收。
4. 对每条路径同时核对服务器事件序号、两端游标与出站队列、领域状态、开放会话位置和屏幕显示；保留可复现脚本、截图与脱敏日志。具体模拟器能力见 `../Android模拟器验收能力需求.md`。
